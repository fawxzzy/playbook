# Repository Memory Event Contract

## Purpose

Playbook episodic memory captures high-signal command outcomes as append-oriented runtime artifacts under `.playbook/memory/`.

This contract defines the repository-local event envelope for `.playbook/memory/events/*.json` and the lookup index `.playbook/memory/index.json`. It matches the shipped engine model (`packages/engine/src/memory/types.ts`, `MemoryEvent`) and the published JSON Schema (`packages/contracts/src/memory-event.schema.json`, registered as `memoryEvent` in `packages/contracts/src/index.ts`).

This contract does **not** alter the structural graph contract (`.playbook/repo-graph.json`) and memory artifacts are **not** regenerated by `playbook index`.

## Scope

This contract governs **episodic memory artifacts** only.

- In scope: time-ordered execution/review/governance events.
- Out of scope: structural graph semantics in `.playbook/repo-graph.json`.

Rule: `.playbook/repo-graph.json` remains structural and is not the temporal event store.

## Storage model

- Event artifacts: `.playbook/memory/events/<eventInstanceId>.json`
- Lookup index: `.playbook/memory/index.json`

Memory artifacts are local runtime state by default and intended to be gitignore-oriented.

## Event envelope (`schemaVersion: "1.0"`)

Fields required by `memory-event.schema.json` (the schema sets `additionalProperties: false`):

| Field | Shape |
| --- | --- |
| `schemaVersion` | constant `"1.0"` |
| `kind` | one of `verify_run`, `plan_run`, `apply_run`, `pr_analysis`, `failure_ingest` |
| `eventId` | non-empty string |
| `eventFingerprint` | non-empty string (deterministic semantic identity) |
| `createdAt` | ISO date-time string |
| `repoRevision` | non-empty string (git revision, or `unknown`) |
| `scope` | `{ modules: string[], ruleIds: string[] }` |
| `sources` | array of `{ type: string, reference: string }` |
| `riskSummary` | `{ level: low\|medium\|high\|unknown, score?: number, signals: string[] }` |
| `outcome` | `{ status: success\|failure\|partial\|skipped, summary: string, metrics?: Record<string, number> }` |
| `salienceInputs` | map of string to string, number, boolean, null, or arrays of those scalars |

Example:

```json
{
  "schemaVersion": "1.0",
  "kind": "verify_run",
  "eventId": "verify_run-<uuid>",
  "eventFingerprint": "<stable hash of normalized event content>",
  "createdAt": "2026-03-12T00:00:00.000Z",
  "repoRevision": "<git revision or unknown>",
  "scope": { "modules": ["engine"], "ruleIds": ["PB001"] },
  "sources": [{ "type": "artifact", "reference": ".playbook/findings.json" }],
  "riskSummary": { "level": "low", "signals": [] },
  "outcome": { "status": "success", "summary": "verify passed" },
  "salienceInputs": {}
}
```

### Compatibility fields written by the engine

`MemoryEvent` in `packages/engine/src/memory/types.ts` also carries `eventInstanceId`, `subjectModules`, and `ruleIds`. The engine writes them on every event: `eventId` is set equal to `eventInstanceId`, and `subjectModules` / `ruleIds` mirror `scope.modules` / `scope.ruleIds`. They exist so older readers keep working (`normalizeMemoryEvent` also accepts legacy events that only have `subjectModules` / `ruleIds`).

Known gap (FACT from code, not yet reconciled): `memory-event.schema.json` does not list these three fields and forbids additional properties, so a strict validation of an engine-written event file against that schema would reject them. Treat the schema as the canonical field set and the mirrors as engine-side compatibility until the schema is revised.

### `eventInstanceId` vs `eventFingerprint`

- `eventInstanceId`: unique capture-instance identity, generated as `<kind>-<uuid>`; names the event file.
- `eventFingerprint`: deterministic semantic identity derived from normalized event content; used for dedupe/clustering across runs.

### Capture behavior

Capture (`captureMemoryEvent`) is subject to the memory admission policy: under pressure a candidate event can be deduplicated, skipped, or rolled up instead of written as a full event. Memory capture is best effort (`captureMemoryEventSafe`) and must not block the primary command.

## Index contract

`index.json` (`kind: "playbook-temporal-memory-index"`, `schemaVersion: "1.0"`) carries `generatedAt`, an `events` array of entries (`eventId`, `relativePath`, `scope`, `fingerprint`, `createdAt`, `memoryKind`), and deterministic lookups:

- `byModule`: module -> event paths
- `byRule`: rule id -> event paths
- `byFingerprint`: semantic fingerprint -> event paths

Each event ref is a repository-relative path (for example `.playbook/memory/events/verify_run-<uuid>.json`). Entries are sorted deterministically.

Pattern: Fast Episodic Store, Slow Doctrine Store.

## Safety rules

Rule: Replay Is Human-Review-Oriented, Not Autonomous Mutation.
Rule: Promotion Required for Durable Doctrine.

Event ingestion must not directly promote doctrine or mutate repository source content without existing policy/remediation gates.

## Failure modes

Failure Mode: Memory Hoarding.
Failure Mode: Rebuilding Durable Memory From Current Repo State Only.
