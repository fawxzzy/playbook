# Contributing to Playbook

Thanks for helping improve Playbook.

## Development Setup

Prerequisites:

- Node.js >= 22
- pnpm >= 10

Install and build:

```bash
pnpm install
pnpm build
pnpm test
```

## Typical Workflow

1. Create a branch for your change.
2. Keep changes focused and aligned with Playbook governance.
3. Run `pnpm build` and `pnpm test` before opening a pull request.
4. Do not update README for new rules or commands; rely on CLI discovery (`playbook --help`, `pnpm playbook rules`, `pnpm playbook explain <id>`).

## Governance Audit Habit

After architecture or governance-adjacent changes run `pnpm playbook audit architecture`, `pnpm playbook doctor` and `pnpm playbook docs audit`; details are in [`docs/contributing.md`](docs/contributing.md#7-governance-audit-workflow).

## Project Areas

- `packages/cli` — command surface and template scaffolding.
- `packages/engine` — analysis and rule verification engine.
- `templates/repo` — files generated by `pnpm playbook init`.
- `docs` — governance, architecture, roadmap, and onboarding documentation.

For contributor setup (prerequisites, workspace tips, pnpm and lockfile policy, tarball testing), adding commands, documentation and testing expectations, and the security checklist, see [`docs/contributing.md`](docs/contributing.md).
